# Panduan Prompt Codex — 4.2 Implementasi Lingkungan Pengujian Blockchain

Dokumen ini menjadi panduan untuk menghasilkan konten **4.2 Implementasi Lingkungan Pengujian Blockchain** menggunakan Codex. Fokusnya adalah menjelaskan **apa yang diimplementasikan**, **bagaimana langkahnya**, dan **hasil terstruktur** yang terlihat (screenshot/tabel/log) sehingga pembaca paham lingkungan uji benar-benar siap dipakai untuk pengujian Raft dan SmartBFT.

---

## 1) Tujuan Penulisan 4.2
Tuliskan bahwa implementasi lingkungan pengujian bertujuan menyiapkan jaringan blockchain Hyperledger Fabric yang siap diuji, dengan dua konfigurasi konsensus yang dibandingkan:

- Network A: Raft (CFT)
- Network B: SmartBFT (BFT)

Penekanan utama: **lingkungan dibuat setara** agar perbandingan adil.

---

## 2) Output Wajib (Hasil Tahap 4.2 harus terlihat)
Konten 4.2 harus menghasilkan bukti/artefak yang jelas, minimal:

1. **Tabel spesifikasi environment** (server/VPS, OS, docker, fabric version, resource)
2. **Bukti network berhasil berjalan**
   - screenshot / output `docker ps`
   - status container orderer/peer/ca berjalan
3. **Bukti channel dan chaincode siap**
   - output create channel sukses
   - output deploy chaincode sukses
4. **Bukti konfigurasi konsensus yang aktif**
   - tunjukkan konfigurasi orderer untuk Raft dan SmartBFT (cukup bagian inti yang membedakan)
5. **Ringkasan topologi jaringan**
   - diagram sederhana atau tabel: org, peer, orderer, channel, chaincode

> Jangan memasukkan hasil TPS/latency/CPU di 4.2. Itu muncul setelah eksekusi transaksi.

---

## 3) Struktur Penulisan yang Disarankan (tidak monoton)
Codex diminta menulis 4.2 dengan pola:
- 1 paragraf pembuka (tujuan implementasi)
- beberapa blok poin yang menjelaskan proses dan bukti
- 1–2 tabel (spesifikasi environment + topologi)
- sisipkan tempat untuk gambar/screenshot dengan caption

---

## 4) Konten Inti yang Harus Ada di 4.2
### A. Spesifikasi Perangkat & Software
Cantumkan dalam tabel:
- OS (misalnya Ubuntu 24.04 LTS)
- Docker & Docker Compose
- Hyperledger Fabric version
- Node.js / Go (jika dipakai)
- Spesifikasi VPS: CPU, RAM, storage
- Jaringan: public/private, port utama yang dibutuhkan

### B. Topologi Lingkungan Uji
Jelaskan topologi dalam bentuk tabel/diagram:
- organisasi (Org)
- jumlah peer per org
- ordering service (Raft / SmartBFT)
- channel yang dipakai
- chaincode yang dipakai

### C. Implementasi Network A (Raft)
Tuliskan poin yang menunjukkan:
- network Raft dibuat dan dijalankan
- layanan penting berjalan (orderer/peer/ca)
- channel dibuat
- chaincode terpasang
- jaringan siap menerima transaksi

### D. Implementasi Network B (SmartBFT)
Tuliskan poin yang menunjukkan:
- network SmartBFT dibuat dan dijalankan
- layanan penting berjalan
- channel dibuat
- chaincode terpasang
- jaringan siap menerima transaksi

### E. Kontrol Kesetaraan Lingkungan
Tuliskan daftar yang dikunci agar fair:
- payload & web prototype sama
- chaincode sama
- channel sama
- environment setara
- prosedur setup sama
- parameter eksekusi nanti mengikuti 4.1

## 7) Prompt Codex (Siap Copy-Paste)
Gunakan prompt ini untuk menghasilkan teks 4.2:

> Tulis bagian **4.2 Implementasi Lingkungan Pengujian Blockchain** dengan bahasa sederhana dan terstruktur. Jelaskan persiapan lingkungan uji Hyperledger Fabric untuk dua jaringan terpisah: **Network A (Raft)** dan **Network B (SmartBFT)**. Tekankan bahwa lingkungan dibuat setara agar perbandingan adil.  
>  
> Wajib ada: (1) tabel spesifikasi environment (OS, Fabric version, Docker version, CPU/RAM/storage VPS), (2) ringkasan topologi jaringan (Org/Peer/Orderer/Channel/Chaincode), (3) bukti network berjalan (contoh output docker ps), (4) bukti channel berhasil dibuat, (5) bukti chaincode berhasil dideploy, (6) bukti konfigurasi konsensus yang aktif untuk Raft dan SmartBFT (cukup bagian inti).  
>  
> Jangan menulis hasil kinerja (TPS/latency/CPU). Gunakan placeholder untuk detail teknis dan perintah (misalnya `{PERINTAH_NETWORK_UP}`) serta sisipkan placeholder gambar dengan caption `Gambar 4.x` dan tabel `Tabel 4.x`. Pastikan alur penjelasan: tujuan → langkah implementasi → bukti/artefak → kesimpulan lingkungan siap diuji.
