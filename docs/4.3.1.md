# 4.3.1 Konfigurasi Pengujian

Dokumen ini mendefinisikan konfigurasi pengujian sistem yang digunakan pada web prototype
untuk analisis kinerja algoritma konsensus Raft dan SmartBFT.
Seluruh parameter pada dokumen ini bersifat **mengikat** dan digunakan sebagai acuan
implementasi serta eksekusi pengujian pada tahap VIBE coding.

---

## 1. Tujuan Konfigurasi Pengujian

Konfigurasi pengujian ditetapkan untuk:
- Menghasilkan data kinerja yang **dapat dibandingkan secara adil**
- Mengisolasi pengaruh **mekanisme konsensus** sebagai variabel utama
- Merepresentasikan dua kondisi sistem:
  - **Baseline (sequential, tidak ramai)**
  - **Beban realistis (parallel, ramai)**

---

## 2. Prinsip Umum (WAJIB)

Parameter berikut **harus sama** untuk seluruh pengujian:

- Payload: dummy write transaction (struktur dan ukuran tetap)
- Chaincode: sama
- Channel: sama
- Environment: sama (VPS, Docker, Fabric version)
- Kriteria sukses transaksi: **committed ke ledger**
- Variabel bebas tunggal: **algoritma konsensus (Raft / SmartBFT)**

---

## 3. Mode Pengujian

Pengujian dibagi menjadi dua mode utama:

### 3.1 Mode Baseline (Sequential)

Mode ini digunakan untuk mengukur **overhead dasar konsensus**
tanpa pengaruh paralelisme atau antrean transaksi.

- Submission pattern: **SEQUENTIAL**
- Concurrency: **1**
- Interval antar transaksi: **0 ms**
- Iterations per skenario: **3**

#### Skenario Baseline

| ID | Transactions per Test | Keterangan |
|---|---:|---|
| B1 | 200 | baseline awal dan validasi stabilitas |
| B2 | 500 | baseline representatif utama |
| B3 | 800 | baseline mendekati batas sistem |

---

### 3.2 Mode Beban Realistis (Parallel)

Mode ini digunakan untuk merepresentasikan kondisi operasional nyata
di mana banyak permintaan transaksi masuk secara bersamaan.

- Submission pattern: **PARALLEL**
- Interval antar request: **0 ms**
- Iterations per skenario: **3**

#### Tingkat Concurrency

Concurrency ditetapkan bertahap untuk mengamati efek koordinasi konsensus:
- **5**  → paralel ringan
- **10** → paralel menengah (utama)
- **20** → paralel tinggi

#### Skenario Parallel

| ID | Transactions per Test | Concurrency | Keterangan |
|---|---:|---:|---|
| P1 | 500 | 5 | beban paralel ringan |
| P2 | 500 | 10 | beban paralel utama |
| P3 | 500 | 20 | beban paralel tinggi |
| P4 | 800 | 5 | scaling + paralel |
| P5 | 800 | 10 | scaling utama + paralel |
| P6 | 800 | 20 | batas performa + paralel |

---

## 4. Skenario Fault Tolerance

Skenario ini digunakan untuk mengamati ketahanan sistem saat gangguan terjadi
dalam kondisi sistem sedang menerima beban.

- Submission pattern: **PARALLEL**
- Transactions per test: **500**
- Concurrency: **10**
- Iterations: **1–2**

| ID | Gangguan | Parameter Dicatat |
|---|---|---|
| F1 | 1 orderer dimatikan saat test berjalan | waktu recovery, tx gagal |
| F2 | 1 orderer direstart saat test berjalan | latency spike, retry |

---

## 5. Aturan Eksekusi (ANTI-RANDOM)

- Setiap skenario **harus dijalankan terpisah** untuk:
  - Raft
  - SmartBFT
- Urutan eksekusi bebas, **namun parameter tidak boleh diubah**
- Jika sistem tidak stabil pada skenario tertentu:
  - catat sebagai **batas lingkungan uji**
  - skenario sebelumnya menjadi batas performa maksimum

---

## 6. Output Minimum per Run

Setiap eksekusi pengujian **wajib menghasilkan data berikut**:

- consensus
- scenario_id
- tx_total
- tx_success
- tx_failed
- start_time
- end_time
- duration_sec
- throughput_tps
- latency_avg_ms
- cpu_usage_avg (jika tersedia)
- memory_usage_avg (jika tersedia)

---

## 7. Catatan Implementasi untuk VIBE Coding

- Codex **tidak diperbolehkan** memilih jumlah transaksi atau concurrency sendiri
- Seluruh nilai harus diambil dari tabel pada dokumen ini
- Dokumen ini menjadi **single source of truth** untuk konfigurasi pengujian

---

Dokumen ini digunakan sebagai acuan implementasi, eksekusi, dan validasi
pengujian kinerja algoritma konsensus Raft dan SmartBFT.
