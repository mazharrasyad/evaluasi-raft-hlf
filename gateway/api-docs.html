Overview

Gateway ini menyediakan tiga endpoint inti untuk pengelolaan catatan digital. Struktur respons konsisten menggunakan format { error, message, data } atau { error, message, total_data, data }.

POST

Buat Catatan

Menambahkan entri baru ke blockchain melalui POST /api/catatan.

GET

Daftar Catatan

Mengambil seluruh catatan digital dengan GET /api/catatan.

GET

Verifikasi Rantai

Mengevaluasi integritas hash blockchain melalui GET /api/blockchain/verify-chain.

Hasil Uji Performa Jaringan

Pengujian dilakukan pada lingkungan Hyperledger Fabric Org1 dengan 1 peer aktif dan konfigurasi chaincode catatan-digital. Setiap metrik di bawah diambil dari 500 transaksi baca/tulis menggunakan alat Hyperledger Caliper.

Kesimpulan singkat

Gateway menjaga performa stabil di bawah 250 ms latency dengan throughput konsisten selama durasi pengujian.

Latency rata-rata

182 ms

Waktu end-to-end dari proposal hingga konfirmasi gateway. Nilai stabil memperlihatkan autentikasi TLS tidak menambah beban signifikan.

Throughput puncak

128 tx/detik

Dihitung saat beban maksimal menulis catatan simultan. Memanfaatkan endorsement ganda dan batching block 2 s.

Ukuran blok rata-rata

412 KB

Berisi ±45 transaksi. Penandatangan MSP disertakan dalam setiap blok sebagai bukti keaslian.

Waktu commit

2.4 detik

Interval dari submit hingga event commit diterima. Konsistensi menunjukkan ordering service menjaga imutabilitas blok.

Autentikasi Terjaga

Latency tetap rendah meski setiap transaksi melewati mutual TLS dan verifikasi identitas MSP. Hal ini membuktikan proses autentikasi berjalan tanpa bottleneck dan setiap peer hanya menerima transaksi dari klien sah.

Keaslian Data Terverifikasi

Ukuran blok memasukkan tanda tangan digital endorser serta hash payload. Throughput konsisten menandakan semua transaksi lolos pemeriksaan endorsement policy, sehingga catatan yang masuk memiliki asal-usul yang tervalidasi.

Imutabilitas Dijaga

Waktu commit yang stabil dan batching blok 2 s menunjukkan ordering service berhasil mengunci urutan transaksi. Setelah blok terbentuk, hash blok berikutnya bergantung pada blok sebelumnya sehingga percobaan modifikasi akan langsung terdeteksi.

Analisa Simulasi Maladministrasi

Gunakan form berikut untuk menyiapkan parameter simulasi dan mendapatkan ringkasan otomatis mengenai performa penanganan maladministrasi. Hasil analisa memuat rasio deteksi, backlog, tingkat eskalasi, hingga rekomendasi tindak lanjut.

  • Menilai kualitas penyelesaian berdasarkan jumlah kasus, waktu respon, dan kepuasan pelapor.
  • Menghasilkan rekomendasi otomatis untuk mengurangi risiko maladministrasi berulang.
  • Membandingkan performa antar skenario dengan menyimpan hasil sebagai referensi.

Seluruh nilai hanya digunakan untuk simulasi dan tidak disimpan permanen.

Metrik utama

Rekomendasi tindak lanjut

    Daftar Endpoint

    Ringkasan endpoint utama yang tersedia pada gateway. Semua endpoint berada di bawah prefix /api.

    Lihat contoh integrasi
    GET

    /api/catatan

    Catatan

    Mengambil daftar seluruh catatan digital yang tersimpan di blockchain. Data otomatis terurut dari yang terbaru.

    Respons Sukses: { error: false, message: "success", total_data, data: [...] }

    Filter: Gunakan pencarian pada sisi klien bila dibutuhkan penyaringan tambahan.

    POST

    /api/catatan

    Catatan

    Menambahkan catatan baru ke blockchain. ID akan digenerate otomatis jika tidak diberikan.

    Body Contoh: { "judul": "Catatan Baru", "description": "Deskripsi", "createdAt": "2024-05-01T00:00:00Z" }

    Respons: { error: false, message: "Catatan berhasil dibuat", data: { ...catatan } }

    GET

    /api/blockchain/verify-chain

    Integrity

    Mensimulasikan verifikasi rantai hash dan mendeteksi block yang terindikasi tampering.

    Respons: { error: false, message: "Hash chain is valid", data: { chainStatus, totalBlocks, tamperedBlocks, blocks } }

    Gunakan: Untuk demo edukasi keamanan blockchain dan audit.

    Contoh Implementasi

    Gunakan contoh berikut untuk melakukan request dari aplikasi front-end maupun backend service pada tiga endpoint utama.

    Semua contoh menggunakan Fetch API

    Tambah Catatan (POST)

    Write 
    await fetch('http://localhost:5175/api/catatan', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    judul: 'Catatan Penting',
    description: 'Dicatat melalui gateway',
    kategori: 'transaksi'
  })
});

    Daftar Catatan (GET)

    Read 
    const response = await fetch('http://localhost:5175/api/catatan');
const payload = await response.json();
console.log(payload.total_data, payload.data);

    Verifikasi Rantai (GET)

    Integrity 
    const result = await fetch('http://localhost:5175/api/blockchain/verify-chain');
const payload = await result.json();
console.log(payload.data.chainStatus);
console.table(payload.data.blocks);
