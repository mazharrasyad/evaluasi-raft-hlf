RAFT Karakteristik Resource

RAFT menggunakan protokol leader-based sederhana dengan 2f+1 node. Overhead resource lebih rendah karena hanya memerlukan majority vote tanpa validasi Byzantine.

Communication Rounds 2 rounds
Message Complexity O(n)
Node Count 3 orderers

SmartBFT Karakteristik Resource

SmartBFT memerlukan lebih banyak resource untuk validasi Byzantine dengan 3f+1 node. Protokol memerlukan lebih banyak communication rounds untuk mencapai konsensus.

Communication Rounds 3 rounds
Message Complexity O(n²)
Node Count 4 orderers

SmartBFT membutuhkan lebih banyak bandwidth karena:

  • Jumlah node lebih banyak (4 vs 3)
  • Message complexity O(n²) vs O(n)
  • Additional signature verification
  • View change protocol overhead

Perbandingan Fault Tolerance

RAFT Karakteristik Fault Tolerance

Model: Crash Fault Tolerant (CFT)

Formula: Dapat toleransi f node crash dari total 2f+1 node

Konfigurasi: 3 orderer (f=1, dapat toleransi 1 crash)

Kelemahan: Tidak dapat mendeteksi node yang berperilaku Byzantine (mengirim data berbeda ke node berbeda)

SmartBFT Karakteristik Fault Tolerance

Model: Byzantine Fault Tolerant (BFT)

Formula: Dapat toleransi f node byzantine dari total 3f+1 node

Konfigurasi: 4 orderer (f=1, dapat toleransi 1 byzantine)

Keunggulan: Dapat mendeteksi dan menangani node yang berperilaku jahat atau mengirim data inkonsisten
