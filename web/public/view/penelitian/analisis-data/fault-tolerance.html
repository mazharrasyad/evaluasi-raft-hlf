Bab 4.5.4

Fault Tolerance

Fault tolerance merupakan kemampuan sistem untuk tetap beroperasi dengan benar meskipun terjadi kegagalan pada satu atau beberapa komponennya. Dalam konteks blockchain dengan algoritma konsensus RAFT, fault tolerance sangat penting karena sistem harus dapat mempertahankan konsistensi data dan melanjutkan operasi normal bahkan ketika beberapa node mengalami kegagalan.

Analisis fault tolerance mencakup pemantauan kejadian kegagalan node (node failures), waktu pemulihan (recovery time), dampak terhadap transaksi yang sedang berjalan, serta verifikasi konsistensi data setelah pemulihan. Metrik ini memberikan gambaran tentang robustness sistem dan kemampuannya dalam menangani skenario failure yang mungkin terjadi di lingkungan produksi.

Parameter yang Mempengaruhi Fault Tolerance

Berikut adalah parameter dan metrik yang digunakan untuk mengukur ketahanan sistem terhadap kegagalan.

Konsensus RAFT dan Fault Tolerance

Max Failures = (N - 1) / 2

RAFT dapat mentoleransi hingga (N-1)/2 node failures, dimana N adalah jumlah total orderer nodes. Dengan 3 orderer, sistem dapat mentoleransi 1 failure. Dengan 5 orderer, dapat mentoleransi 2 failures.

Data Consistency

Verifikasi konsistensi data setelah pemulihan

Konfigurasi Orderer dan Fault Tolerance

3 3 Orderer Nodes (Standard)

Dapat mentoleransi 1 node failure. Minimal untuk fault tolerance.

5 5 Orderer Nodes (Variant)

Dapat mentoleransi 2 node failures. Lebih robust untuk production.

Faktor-faktor yang Mempengaruhi Fault Tolerance

1 Number of Orderers

Lebih banyak orderer = lebih tinggi fault tolerance.

2 Election Timeout

Waktu untuk mendeteksi leader failure dan memilih leader baru.

3 Heartbeat Interval

Frekuensi heartbeat antar node untuk deteksi kegagalan.

4 Network Latency

Latency tinggi dapat menyebabkan false positive failure detection.

5 Snapshot Interval

Frekuensi snapshot untuk mempercepat recovery.

6 Log Replication

Kecepatan replikasi log mempengaruhi waktu recovery.

Catatan Penting

  • 1. Untuk menguji fault tolerance, hentikan secara manual beberapa orderer node selama simulasi berjalan.
  • 2. Success rate > 95% selama failure mengindikasikan fault tolerance yang sangat baik.
