Algoritma Raft

Halaman ini membahas flow dan pseudocode algoritma konsensus Raft pada Hyperledger Fabric versi 2 dan 3, serta varian dengan SmartBFT.

Flow Algoritma Raft

  1. Leader menerima transaksi dari client.
  2. Leader membentuk batch/blok dari transaksi.
  3. Leader mengirim AppendEntries (blok) ke follower.
  4. Follower menulis log dan mengirim ack ke leader.
  5. Jika mayoritas follower ack, blok di-commit dan didistribusikan ke peer.
  6. Pada kegagalan leader, pemilihan leader baru dilakukan (election).

Pseudocode Raft (HLF v2 & v3)

// Leader menerima transaksi
onReceiveTransaction(tx):
    batch.append(tx)
    if batch.size >= batchSize or timeout:
        block = createBlock(batch)
        for follower in followers:
            send AppendEntries(block) to follower
        batch.clear()

// Follower menerima blok
onAppendEntries(block):
    log.append(block)
    send Ack to leader

// Leader menerima ack
onAck(follower):
    ackCount[follower] += 1
    if ackCount quorum:
        commit(block)
        broadcast block to peers

// Election
onTimeout():
    becomeCandidate()
    startElection()

Varian Raft dengan SmartBFT (HLF v3)

Pada Fabric v3, SmartBFT menjadi opsi konsensus BFT. Flow mirip Raft, namun menggunakan protokol BFT (Byzantine Fault Tolerance) dengan quorum lebih besar dan mekanisme validasi tambahan. 

// SmartBFT (skema sederhana)
onProposeBlock(block):
    broadcast PrePrepare(block) to all

onPrePrepare(block):
    if valid(block):
        broadcast Prepare(block)

onPrepare(block):
    if receive Prepare from quorum:
        broadcast Commit(block)

onCommit(block):
    if receive Commit from quorum:
        commit(block)
        broadcast block to peers
