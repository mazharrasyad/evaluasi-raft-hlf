Bab 4.6.1.1

Fabric v2 — Raft Standar

Konfigurasi ini menempatkan satu orderer leader dengan quorum CFT untuk menjaga konsistensi log. Fokus utama adalah stabilitas latency dan prediktabilitas commit saat beban transaksi normal.

Analisis Konfigurasi

Raft standar di Fabric v2 menekankan kestabilan batch dan alur replikasi yang sederhana. Leader membangun blok dari batch stabil, mengirim AppendEntries ke follower, lalu menunggu mayoritas ack sebelum commit.

Sorotan

  • • 1 leader + 2 follower (quorum 2/3).
  • • Batch size stabil, timeout moderat.
  • • Commit deterministik setelah mayoritas ack.

Trade-off

  • • Throughput moderat, namun konsisten.
  • • Skalabilitas orderer terbatas.
  • • Recovery sederhana saat follower tertinggal.

Parameter Utama

Jumlah orderer 3 (1 leader, 2 follower)
Batch size Stabil (konservatif)
Target Latency konsisten

Tekan tombol simulasi untuk memulai alur transaksi.

  1. Tx diterima oleh leader — transaksi masuk dan masuk ke batch stabil.
  2. Leader membuat blok — batch memenuhi threshold dan dibundel.
  3. AppendEntries ke follower — blok direplikasi ke quorum.
  4. Mayoritas ack — leader menerima konfirmasi dan memutuskan commit.
  5. Broadcast ke peer — blok dikirim ke peer untuk apply state.
