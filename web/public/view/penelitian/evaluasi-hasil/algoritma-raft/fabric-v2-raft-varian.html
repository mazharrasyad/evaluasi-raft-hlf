Fabric v2 — Raft Varian

Varian Raft di Fabric v2 memperbesar cluster orderer dan mengadopsi batching agresif. Tujuannya adalah meningkatkan throughput pada beban transaksi tinggi, dengan biaya tambahan koordinasi antar orderer.

Analisis Konfigurasi

Di skenario varian, leader memanfaatkan orderer tambahan untuk mempercepat replikasi. Batch dibentuk lebih agresif untuk menekan overhead per transaksi, namun meningkatkan risiko lonjakan latency saat quorum belum lengkap.

Sorotan

  • • 1 leader + 4 follower (quorum 3/5).
  • • Batch agresif untuk throughput tinggi.
  • • Parallel AppendEntries untuk efisiensi.

Trade-off

  • • Throughput naik, latency bisa fluktuatif.
  • • Overhead jaringan lebih besar.
  • • Recovery follower memerlukan koordinasi ekstra.
