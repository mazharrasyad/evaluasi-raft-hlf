Bab 4.4.3

Pembuatan Data Simulasi

Pembuatan data simulasi dirancang untuk mengevaluasi performa sistem blockchain Hyperledger Fabric dengan konsensus Raft dalam berbagai kondisi beban. Data simulasi menggunakan konteks pelaporan maladministrasi di Indonesia dengan total 10.837 laporan pada tahun 2024 sebagai acuan untuk menciptakan skenario yang realistis.

Kriteria Beban Simulasi

Kriteria beban simulasi dibagi menjadi tiga kategori untuk mengevaluasi performa sistem dalam kondisi operasional yang berbeda:

Kategori 1

Beban Ringan

Kondisi normal dengan jumlah transaksi rendah, menggambarkan aktivitas harian yang stabil dengan distribusi laporan merata.

Volume Transaksi
100-500 transaksi
≈ 0.9% - 4.6% dari total laporan tahunan
Throughput Target
10-20 TPS
Transactions Per Second
Skenario
Simulasi aktivitas harian normal dengan distribusi merata berdasarkan proporsi data 2024. Mencakup laporan dari berbagai substansi dengan dominasi Agraria (17.2%), Kepegawaian (12.5%), dan Pendidikan (9.6%).
Distribusi Data
Pelapor: 77% Perorangan, 8% Badan Hukum
Terlapor: 47% Pemda, 12% BPN
Kantor: Distribusi merata 34 kantor regional + pusat
Periode: Distribusi merata per hari/minggu
Kategori 2

Beban Sedang

Kondisi aktivitas menengah dengan peningkatan volume transaksi, menggambarkan periode aktivitas tinggi namun masih terkendali.

Volume Transaksi
1.000-3.000 transaksi
≈ 9.2% - 27.7% dari total laporan tahunan
Throughput Target
50-100 TPS
Transactions Per Second
Skenario
Simulasi periode sibuk seperti akhir bulan atau awal tahun ketika terjadi peningkatan laporan. Fokus pada substansi dengan volume tinggi: Agraria, Kepegawaian, Pendidikan, dan Perhubungan yang secara kumulatif mencakup 52% dari total laporan.
Distribusi Data
Pelapor: 75% Perorangan, 10% Badan Hukum
Terlapor: 50% Pemda, 15% BPN, 10% BUMN/BUMD
Kantor: Fokus pada 10 kantor tersibuk (Jakarta, Sulsel, Jambi, Bali, dst)
Periode: Konsentrasi pada jam kerja (08:00-16:00)
Kategori 3

Beban Tinggi

Kondisi puncak ketika terjadi lonjakan transaksi secara signifikan, menggambarkan situasi krisis atau kejadian luar biasa yang memicu pelaporan massal.

Volume Transaksi
5.000-10.000 transaksi
≈ 46.1% - 92.3% dari total laporan tahunan
Throughput Target
200-500 TPS
Transactions Per Second
Skenario
Simulasi kondisi ekstrem seperti viral case atau bencana yang memicu lonjakan pelaporan massal. Mencakup semua kategori substansi dengan penekanan pada substansi yang paling sering dilaporkan dan melibatkan semua 34 kantor penerimaan laporan secara bersamaan.
Distribusi Data
Pelapor: 80% Perorangan, 12% Kelompok Masyarakat
Terlapor: 55% Pemda, 14% BPN, 8% BUMN/BUMD
Kantor: Seluruh 34 kantor aktif bersamaan
Periode: Burst traffic dalam 2-4 jam puncak

Implementasi Teknis

Format Data Simulasi

Setiap transaksi laporan dalam simulasi akan memiliki struktur data sebagai berikut: 

{
  "reportId": "RPT-2024-XXXXX",
  "timestamp": "2024-12-31T14:30:45.123Z",
  "substance": "Agraria (Pertanahan dan Tata Ruang)",
  "reporterGroup": "Perorangan",
  "reportedGroup": "Pemerintah Daerah",
  "receivingOffice": "Jawa Barat",
  "description": "Deskripsi singkat laporan maladministrasi",
  "status": "pending"
}

Strategi Pembangkitan Data

1. Distribusi Proporsional

Gunakan distribusi weighted random berdasarkan persentase data 2024 untuk setiap atribut (substansi, pelapor, terlapor, kantor).

2. Timestamp Realistis

Untuk beban ringan: distribusi merata sepanjang hari. Untuk beban sedang: konsentrasi pada jam kerja. Untuk beban tinggi: burst dalam 2-4 jam puncak.

3. Korelasi Data

Pertahankan korelasi logis seperti laporan Agraria cenderung dilaporkan ke BPN, laporan Pendidikan ke Lembaga Pendidikan Negeri, dll.

4. ID Unik Sequential

Generate report ID dengan format RPT-2024-XXXXX dimana XXXXX adalah nomor sequential untuk memudahkan tracking dan analisis.

Tools dan Scripts

Implementasi pembangkitan data menggunakan scripts khusus yang tersedia di direktori simulasi:

• generate-light.js — Script untuk membangkitkan data beban ringan
• generate-medium.js — Script untuk membangkitkan data beban sedang
• generate-high.js — Script untuk membangkitkan data beban tinggi
• validate-data.js — Script untuk validasi distribusi data
