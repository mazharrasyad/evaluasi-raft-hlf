Bab 4.2

Perumusan Rancangan Eksperimen

Rancangan eksperimen disusun untuk memastikan evaluasi kinerja konsensus RAFT berlangsung secara sistematis, terkontrol, dan dapat direplikasi. Desain ini mengatur cara membandingkan RAFT standar dengan RAFT varian di dua versi platform Hyperledger Fabric sekaligus menetapkan parameter serta variabel uji yang terukur. Sejalan dengan metodologi pada Bab III, penelitian ini menerapkan pendekatan eksperimen kuantitatif dengan desain komparatif.

Bab 4.2.1

Desain Eksperimen

Eksperimen dirancang secara komparatif dengan mengendalikan variabel di luar fokus penelitian sehingga perbedaan hasil kinerja dapat dikaitkan langsung dengan implementasi RAFT yang diuji. Empat kondisi pengujian disiapkan untuk mengamati variasi performa di lintas versi platform dan konfigurasi konsensus.

  1. RAFT standar pada Fabric v2
  2. RAFT varian pada Fabric v2
  3. RAFT standar pada Fabric v3
  4. RAFT varian pada Fabric v3

Skema tersebut memungkinkan evaluasi menyeluruh terhadap konsistensi perbedaan kinerja antarversi platform. Untuk menggambarkan variasi pelaporan maladministrasi, tiga kategori beban transaksi digunakan: beban ringan untuk kondisi harian, beban sedang untuk periode aktivitas menengah, dan beban tinggi sebagai stress test saat pelaporan massal. Setiap skenario diulang beberapa kali guna menghitung nilai rata-rata, standar deviasi, dan memastikan dasar statistik yang valid.

Replikasi & Reliabilitas

Pengulangan setiap skenario memungkinkan analisis variansi serta pengujian hipotesis atas perbedaan rerata kinerja antar konfigurasi RAFT.

Simulasi Kegagalan

Eksperimen fault tolerance menghentikan orderer leader untuk mengamati durasi pemilihan pemimpin baru, waktu pemulihan jaringan, dan konsistensi data pascakrisis.

Bab 4.2.2

Parameter dan Variabel Uji

Evaluasi menitikberatkan empat aspek kinerja: throughput, latency, resource usage, dan fault tolerance. Variabel yang dimanipulasi dan diukur ditetapkan untuk menangkap pengaruh langsung dari konfigurasi RAFT serta versi platform Fabric terhadap performa sistem.

Variabel yang Dimanipulasi

  1. Jenis konfigurasi RAFT: standar (default) versus varian dengan penyesuaian parameter.
  2. Versi Hyperledger Fabric: v2 sebagai rilis stabil dan v3 sebagai rilis pengembangan.
  3. Tingkat beban transaksi: ringan, sedang, dan tinggi sesuai kelas aktivitas pelaporan.

Variabel yang Diukur

  1. Throughput untuk menilai kemampuan jaringan memproses transaksi per satuan waktu.
  2. Latency untuk mengukur waktu respons dari pengajuan sampai konfirmasi ledger.
  3. Resource usage yang memantau konsumsi CPU dan memori pada node orderer maupun peer.
  4. Fault tolerance untuk mengamati ketahanan sistem terhadap kegagalan node, waktu pemulihan, dan konsistensi data.

Validitas eksperimen dijaga dengan menyamakan jumlah serta konfigurasi node, parameter blok, chaincode, dan spesifikasi perangkat keras pada seluruh skenario. Kombinasi variabel menghasilkan 12 kondisi pengujian yang mencakup:

  1. RAFT standar pada Fabric v2 dengan beban ringan, sedang, dan tinggi.
  2. RAFT varian pada Fabric v2 dengan beban ringan, sedang, dan tinggi.
  3. RAFT standar pada Fabric v3 dengan beban ringan, sedang, dan tinggi.
  4. RAFT varian pada Fabric v3 dengan beban ringan, sedang, dan tinggi.

Struktur pengujian ini menghadirkan perbandingan komprehensif antara RAFT standar dan varian di kedua versi Fabric serta pada beragam tingkat beban transaksi, sehingga temuan kinerja dapat ditarik secara andal.
