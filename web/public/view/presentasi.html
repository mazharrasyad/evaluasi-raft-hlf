Presentasi Bab 4

Ringkasan Kilat Penelitian

Satu kartu untuk setiap halaman penting di Bab 4. Gunakan daftar ini sebagai deck presentasi cepat: setiap entri langsung menyebut tujuan, fokus, dan highlight teknis yang perlu diingat saat memaparkan hasil evaluasi RAFT pada Hyperledger Fabric.

Riset Inti

Bab 4.1 – 4.3

4.1

Gambaran Umum Penelitian

Menetapkan konteks evaluasi RAFT untuk kasus pelaporan maladministrasi nasional.

  • Volume 10.846 aduan 2024 dipakai sebagai dasar skenario beban transaksi.
  • Fabric 2 & 3 dengan RAFT CFT jadi fokus perbandingan throughput, latency, resource, dan ketahanan.
4.2

Rancangan Eksperimen

Framework komparatif untuk RAFT standar vs varian.

  • Empat konfigurasi (Fabric v2/v3 × standar/varian) diuji pada tiga level beban.
  • Pengulangan dan fault-injection (leader failover) memastikan hasil signifikan secara statistik.
4.3

Pembangunan Lingkungan Uji

Testbed simetris untuk Fabric 2 dan 3.

  • Struktur folder identik (bin, chaincode, config, env, network) memudahkan replikasi eksperimen.
  • Parameter RAFT dibedakan (BatchTimeout 2s→1s, MaxMessageCount 10→50, opsi SmartBFT) guna mengejar throughput tinggi.

Pelaksanaan Simulasi

Bab 4.4

4.4

Pipeline Simulasi

Ikhtisar langkah pembuatan channel, deployment chaincode, injeksi data, dan pengambilan hasil.

  • Setiap tahap dibakukan agar perbandingan antar konfigurasi bersifat apple-to-apple.
  • Fabric v3 varian menambahkan opsi SmartBFT sebagai pembanding RAFT.
4.4.1

Pembuatan Network

Dashboard operasional untuk Fabric 2 & 3 (standar dan varian).

  • Start, stop, restart massal, dan health check memakai SSE status feed.
  • Menjamin channel & chaincode siap sebelum skenario simulasi dijalankan.
4.4.2

Perancangan Data Simulasi

Dataset sintetis berbasis statistik 10.837 laporan 2024.

  • Tiga kategori beban: 100–500, 1k–3k, 5k–10k transaksi dengan target 10–500 TPS.
  • Memuat distribusi substansi, kelompok pelapor/terlapor, kantor, dan periode pelaporan.
4.4.3

Pengeksekusian Simulasi

Generator transaksi yang dapat memilih load, network, dan concurrency.

  • Merekam submittedAt & completedAt untuk setiap tx agar TPS/latency otomatis dihitung.
  • Fault tolerance optional: node failure, network partition, timeout, invalid tx, dsb.
4.4.4

Penyimpanan Data

Viewer gabungan untuk ledger empat network.

  • Mengonsumsi API GET pelaporan per network dan menampilkannya via DataTables.
  • Memudahkan audit hasil simulasi dan validasi payload yang tersimpan.

Analisis Data

Bab 4.5

4.5

Kerangka Analisis

Semua hasil simulasi diringkas ke empat KPI.

  • Throughput, latency, resource usage, dan fault tolerance dijadikan panel analitik.
  • Memudahkan komparasi RAFT standar vs varian dan opsi SmartBFT di Fabric 3.
4.5.1

Throughput

Menghitung TPS = total transaksi / durasi.

  • Ringkasan per network + grafik throughput per data dengan filter kategori beban.
  • Menyoroti percepatan atau bottleneck saat konfigurasi batch diubah.
4.5.2

Latency

Distribusi waktu respons dari submittedAt ke completedAt.

  • Menampilkan average, min, max, P50, P95, P99 untuk melihat konsistensi.
  • Menjelaskan faktor latency: network, endorsement, ordering, block batching, commit.
4.5.3

Resource Usage

Monitoring CPU, memory, dan IO dari container docker.

  • Snapshot orderer & peer tiap network untuk mengukur efisiensi konfigurasi.
  • Mengaitkan konsumsi resource dengan hasil throughput/latency.
4.5.4

Fault Tolerance

Menilai ketahanan RAFT saat terjadi gangguan.

  • Mencatat success rate, failure count, node failure detail, dan recovery time.
  • Menunjukkan dampak penghentian orderer leader saat load berjalan.
